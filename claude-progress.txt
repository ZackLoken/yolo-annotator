What shipped
------------

All 20 tasks of the plan are implemented and review-clean. The two-tab
Annotate/Review design is gone. There is now one canvas: predictions draw
as a layer on it, accept/reject promotes or deletes annotations in place,
a queue steps through every prediction/annotation pairing, and a single
canvas banner is the only feedback channel outside the one quit-without-
saving modal. Import predictions is a form on the toolbar. Completion and
blind review are wired through AnnotationStats. Packaging (PyInstaller
windowed one-directory build) and documentation (README.md, CLAUDE.md)
are updated.

Test suite: pytest -q, 208 passed, run at HEAD (commit eeb3c0f). This
count has been stable across multiple runs today; a headed smoke test can
occasionally show as skipped locally due to pre-existing Tk/Tcl init
flakiness in this conda environment (documented since Task 9), not a
project defect. CI runs headless on ubuntu-latest and should show that
smoke test skip consistently rather than fail, after this session's Task
20 fixes (see below).

Task 20, the plan's final adversarial review and hand-off, is done through
its first two steps:

Step 1, a whole-branch review on the most capable model, found two
Critical bugs invisible to any single task's own review:
- _open_folder bypassed the save gate entirely, silently discarding an
  unparseable label line's content the moment a different folder was
  opened, with a failed save's error swallowed by a print.
- undo() and redo() rolled back verdicts in memory but never persisted
  review_stats.json, so an undo did not roll back what is recorded as
  ground truth for the blind-vs-assisted recall comparison the whole
  redesign exists to produce, and this survived a restart.
Plus eight Important findings: accept/reject not saving the document
immediately; two headed smoke tests that would fail rather than skip on
real CI; three remaining messagebox pop-ups violating the single-feedback
rule; five print() calls invisible in the packaged (console=False) build;
classes.json being the one state file not protected by quarantine, so a
corrupt one got silently overwritten; a pre-existing bug (found and
ledgered back in Task 11) where launching the app wrote an empty
classes.json into the working directory instead of the opened folder;
duplicate label lines silently collapsing to one sidecar record; and the
.original/ label backup only firing on accept/reject, narrower than what
the documentation promised.

Step 2, fixing those findings, is complete: 9 commits
(8942482, 76e2394, e470faa, f71c8cb, 099b4c1, 71f7788, 12285fa, cfbe907,
eeb3c0f), all ten Critical/Important findings fixed with regression tests
that assert real on-disk file content, not just in-memory state (that
distinction is exactly what let the two Critical bugs through every
earlier review). A scoped re-review independently verified every finding
against the actual code and traced the trickiest fixes (the duplicate-
label occurrence-index key, the classes.json construction-order guard)
through their read and write paths rather than trusting the fix report.
Two low-severity items surfaced in the fix diff itself and were parked
rather than fixed: classes.json can now raise on a genuine OS-level read
failure instead of degrading gracefully (matches the other two state
files, which already had this same gap); and a cosmetic handler-rebinding
issue in the new canvas-message helper with no observable effect.
